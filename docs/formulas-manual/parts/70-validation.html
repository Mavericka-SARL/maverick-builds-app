17. Validation, troubleshooting and limits

What the save refuses

Saving a metric (the Add metric form, the row editor or the AI Developer) checks the whole formula against the revision. A refused formula is not saved, and the message appears under the form, as below.

Checked later, when the dimensions are known

Some rules depend on where a metric sits. They are checked again when a metric is placed on a grid, when a dimension is removed from a grid, and when a revision is activated:

  • a LOOKUP or SUMIFS source whose dimensions do not include the argument dimension (DIMENSION_NOT_ON_SOURCE), when the source was not yet on a grid at save;
  • a literal TIMESUM period code that is not a period of the grid's time dimension (UNKNOWN_MEMBER), and a literal LOOKUP code renamed since;
  • a time function on a grid without exactly one time dimension (TIME_DIMENSION_REQUIRED, MULTIPLE_TIME_DIMENSIONS).

Changing what formulas name

  • Renaming a property rewrites every formula that reads it (region.old becomes region.new).
  • Deleting a property, a dimension or a member that a formula names is refused (PROPERTY_IN_USE, DIMENSION_IN_USE, MEMBER_IN_USE), and the message lists the metrics to change first.
  • Renaming a member does not rewrite formulas: a literal naming the old code then fails with #N/A, and activation refuses the revision until the formula is changed.
  • Deleting a metric that another metric reads — in its formula, or as the numerator or denominator of its Rate total — is refused with METRIC_IN_USE (HTTP 409), and the message lists those metrics: "units is read by arg_aggs, logic_mix, price; change those metrics first, then delete it". The Used by column shows the formula readers in advance, and the confirmation names them. A metric reading only itself (PREVIOUS(x) in x) does not block its own delete.

Troubleshooting

SymptomLikely cause and what to do
A warning triangle beside the formulaSome cells failed. Hover it for the first error; typical: a division by a zero that is not "no data", a member code that does not exist (#N/A), a dynamic offset that is not whole.
A cell is empty ("—")Its formula failed there; or it read only zeros and failed (no data); or the result is blank (a property the member has no value for, a *VALUE of a metric with summary none); or, for a user, it is withheld (chapter 15).
A total looks wrongCheck the aggregation rule and time summary (chapter 15). Ratios need Formula or Rate; balances need last/first.
0 where a value was expectedA metric with nothing recorded reads 0. A plain reference to a metric on another grid reads its total over the dimensions the cell lacks: use LOOKUP to choose a member. A dimension or property at a total is blank.
A condition never matchesNumbers compare on 15 significant digits, so a real difference beyond rounding noise is the cause: compare ROUND(x, 2) to ignore cents. Text compares ignoring case, so case is not the problem. A number against text compares as text.
A metric that reads no other metric did not updateIt recalculates when saved or when the revision is activated, not when inputs change (it has no inputs).
DIM_CONTEXT_REQUIRED or TIME_CONTEXT_REQUIREDA dimensional or time function evaluated where it has no cell: place the metric on a grid with the dimensions it names.

Not available

  • Cell addresses and ranges (A1, A1:B9), external workbooks, array formulas, named ranges, the % suffix.
  • XLOOKUP, VLOOKUP, INDEX, MATCH (use LOOKUP by member), SUMPRODUCT, VALUE, ISBLANK, ISNUMBER, ISERROR and the other IS… functions (use IFERROR, IFNA, or x = "" for blank), functions listing a member's children (LOOKUP of the parent already combines them).
  • The time functions POST, SPREAD, PROFILE and WEEKVALUE; MOVINGSUM windows that are not literals; mapping between two time dimensions.
  • Text or date results stored as such: every result is a number.
  • Formulas on form fields. Forms post into input metrics; formulas live on calculated metrics.
  • JavaScript, Python or SQL in formulas.
