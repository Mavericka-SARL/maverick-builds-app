Forms

Sidebar: Build › Forms

A form is a structured record type that business users fill in: a purchase request, an expense claim, a headcount change. This screen defines the schema only. Records are entered and reviewed by business users in their console; posting form values into planning cells is configured under Integrations › Form Records.

Controls

ControlWhat it does
New form / CancelOpens or closes the create panel. Closing resets it to one blank text field.
Form nameTechnical name, snake_case. Typing is coerced: lowercase, any character other than a–z, 0–9 and underscore becomes an underscore. Example placeholder: purchase_request.
Display labelWhat users see, free text.
Fields rowsOne row per field: field_name (same coercion as the form name), Field label, Field type, Required checkbox, remove icon. Add field appends a text field.
Field typeText, Number, Date, Select, Boolean, Metric, and under the group Dimensions one entry per dimension of the model. A dimension field stores a member of that dimension. Changing the type clears any type-specific settings.
Metric field optionsBy ID (fixed): the field is tied to one input metric chosen from Metric (only input metrics are offered). By name (dynamic): the record names the metric at runtime and the Amount field select picks which Number field of the form carries the value.
Create formEnabled once name, label and every field name are filled. Errors are shown under the button.
Edit on a cardOpens the same editor inline for that form. Save shows a green Saved for a moment and closes; Cancel discards.
Delete iconConfirm Delete form?: "This removes the form and all its submitted records."

Rules and behaviour

  • Forms are per revision. The list and the create action use the selected revision. Editing never moves a form to another revision.
  • Same name overwrites. Creating a form whose technical name already exists in the revision silently replaces that form's label and fields. Pick a new name for a new form.
  • Delete cascades. Deleting a form removes every dashboard widget that shows it and every record ever submitted to it.
  • Records live in the business console. Business users create, view and export records there (CSV and XLSX). The developer screen has no record controls.
  • Posting to cells is a separate object. A form mapping (Integrations › Form Records) decides which field feeds which input metric, at which dimension members, for which record statuses. Metric and Dimension field types exist so the mapping has something to read.
  • Where forms appear. Business users open a form through a dashboard Form widget. A form that is on no dashboard is not reachable by them.

Grids

Sidebar: Build › Grids

A grid is a selection of metrics and dimensions that is shown as one table. It holds no data of its own; the data lives in the model. The same metric can only sit in one grid, so grids partition the model's metrics into the tables users will edit.

Controls

ControlWhat it does
New grid / CancelShows the create row. Grid name is free text (placeholder OPEX Budget); Create is enabled once it is filled.
Card headerName and "n metrics · n dimensions".
Configure / DoneExpands one grid at a time. Done just collapses; nothing is pending.
Search metrics…Filters by display label or technical name.
Metric checkboxesTicked = in this grid. Each metric shows an Input or Calc badge. Sections In this grid (n) and Available (n).
Search dimensions…Filters by dimension name.
Dimension checkboxesTicked = axis of this grid. Shows the member count.
Show: level selectAppears only for a ticked dimension that has a hierarchy. Options: All levels (hierarchy), Root only (level 0), Level 1 only … Level N only, Leaves only. Controls which level of the hierarchy the grid shows as its axis.
Delete iconConfirm Delete grid?: "This removes the grid from all dashboards that use it."

Rules and behaviour

  • One grid per metric. Ticking a metric that already belongs to another grid is refused by the server and the box stays unticked after refresh. Untick it in the other grid first. Dimensions can be shared freely.
  • Same revision. Metrics and grid must be in the selected revision; a mismatch is refused.
  • Deleting a grid deletes its widgets. Every dashboard widget that showed the grid disappears; the dashboards themselves stay.
  • No rename. The screen has no rename control; create a new grid if the name must change.
  • Where the table comes from. A grid becomes visible to users through a dashboard Grid widget (Dashboards chapter). The widget decides which dimension is rows, columns or a selector; the grid only decides the ingredients.
  • Level display. Choosing Leaves only hides parent members from the axis; totals for parents are still computed and appear where the widget shows them.
