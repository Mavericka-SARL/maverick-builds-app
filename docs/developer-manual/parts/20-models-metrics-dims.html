Models

Sidebar: Build › Models

The Models screen lists every application and model you can reach, with their revisions. It is where you choose which revision you are editing; every other Build screen works inside that choice.

Controls

ControlWhat it does
Banner Working in revision: …The revision every Build screen edits, with its short id. With nothing selected the banner is orange: "No revision selected — select a revision below to start working".
Revision rowClick to select it. The row gets a Working badge; a live badge marks the model's active revision.
Set activeOn a non-active revision. Confirm Set as active revision?: the revision "becomes the live revision everyone sees. This can be changed again later."
Delete revision iconOn a non-active revision. Confirm Delete revision?: "This permanently removes the revision. This cannot be undone." The active revision cannot be deleted.
New revisionType a name, press Enter or Save. The new revision is a full copy of the model's current state (see Concepts › Revisions).
Set as business default / badge business defaultBusiness consoles (dashboards, workflows, grids) open the default model of an application. With several models in one application, pick which one users get.

Rules and behaviour

  • Selection is per session and not saved. On a fresh sign-in the console pre-selects the most recently created revision, and if you skip this screen it falls back to a default revision that may belong to another application. Check the header (Model and Revision) before creating anything.
  • Applications and models are created by administrators (Applications screen of the tenant or platform admin). A developer creates revisions, not applications.
  • Active means live. Business users always see the active revision. Build and test in a non-active revision, then Set active.

Metrics

Sidebar: Build › Metrics

A metric is a measure of the model: an Input metric is typed in by users, imported or posted from forms; a Calc metric is computed from a formula over other metrics. The list groups inputs first, then a Calculated section.

The list

Tag chipsOne chip per tag used on a metric, beside the search. Choosing one shows only the metrics carrying it; choosing it again, or a tag on a row, clears or switches the filter.
Header lineApp and model name and the model's short id, so you can confirm what you are editing.

A metric that another metric reads, in its formula or as the numerator or denominator of its Rate total, cannot be deleted: the refusal (METRIC_IN_USE) appears under the row and names those metrics.
Add metric / CancelOpens the add form under the list. Its last field, Tags, takes free-form labels: type one and press Enter or comma. Tags are stored lower case with spaces as hyphens, and the row editor has the same field.

The add form

FieldMeaning
Metric nameTechnical name in snake_case; formulas refer to it, in any case. Example gross_margin. A name another metric of the revision already has, even in another case, is refused (METRIC_NAME_TAKEN); so is a dimension name that differs from an existing dimension's only in case (DIMENSION_NAME_TAKEN). A metric may not take a dimension's name, nor a dimension a metric's (NAME_IS_OTHER_KIND): in a formula the name could mean either, and a formula saved while only one existed stays bound to it. Display nameOptional. What grids, charts, KPI tiles and forms show for the metric, such as R&D or EBITDA Margin, which a snake_case name cannot spell. Left blank, it is the name in title case (gross_margin shows as Gross Margin); cleared later, it goes back to that. Revision copies and model export carry it.
TypeCalc or Input. Choosing Input clears the formula.
FormatNumber, Percentage, Currency, Boolean, Text, Pick-list. Currency adds Decimal places (0–4) and Symbol (default $). Number and Percentage also take decimal places. Pick-list asks for Members of — a dimension of the revision — and each cell then holds one member of it, chosen from a list in the grid (see Pick-lists below).
Formula (Calc only)Spreadsheet-style expression over metric and dimension names, for example =revenue - cogs (the older {hc_cost} + {software_cost} form still works). Names that are neither a metric nor a dimension of the revision are listed below the field as you type ("Not a metric or dimension in this revision: …"), regardless of case; the list is a hint and does not block Add metric. The full language is in the Formulas Manual.
Aggregation ruleHow per-member results combine into totals: Sum, Average, Count, Rate, Formula, None (no total). Rate asks for a Numerator and a Denominator metric ("total = numerator ÷ denominator"), so the total reflects weight instead of averaging members. Formula evaluates this metric's own formula on aggregated inputs, which is what ratios and percentages need; it is refused for input metrics. None gives a value at the metric's own members only and nothing on a total row — a priority index or a correction % typed per region, whose company total means nothing (a spreadsheet's blank total cell); time still totals by the time summary. A pick-list input is always None; a calculated pick-list is Formula (its formula on the total row, as a spreadsheet's total-row status) unless set to None.
Time summary (shown when the revision has a Time dimension; in the row editor only for metrics on a grid that carries one)How the metric totals across time, independently of the aggregation rule: sum for flows (revenue, cost), last for a closing balance, first for an opening balance, average, min, max, or none when a time total is meaningless (no total is shown). A non-default choice shows as a "time: last" badge on the row.
Add metricEnabled when the name is filled, a Calc metric has a formula, and a Rate rule has both operands. The server then checks the whole formula and shows its message if it refuses it. After success the label reads Added and the form stays open for the next metric.

Editing

  • Saving a changed formula or rule triggers recalculation; the row then shows a green Recalc results banner listing "revision → metric = value" per affected total. Dismiss it with the ×.
  • While you type, names that are neither a metric nor a dimension of the revision are listed under the field ("Not a metric or dimension in this revision: …"), whichever style you use (name or {name}). That is a hint and never blocks Save: the server checks the formula when you save and shows its message if it refuses it.
  • The type (Input or Calc) cannot be changed after creation; create a new metric instead.
Pick-lists: a cell that holds a dimension member. Where a spreadsheet has a drop-down — Yes / No, a Status of Draft, Committed or Cancelled, a target method, an activity's Region — make the options a small dimension (its members are the options, labelled as people should read them) and give the metric the format Pick-list over it. In the grid each cell is a list of that dimension's members (calculated members excluded) and "—" clears it; the server refuses anything that is not one of them. In a formula the pick-list reads as the member's code: IF(include_strategic = "Yes", …), act_status <> "Cancelled", LOOKUP(fx_rate, currency, act_currency), and it can be a criteria range — SUMIFS(strat_sales, act_region, region) adds the activities whose Region cell holds the row's region. A calculated pick-list's formula gives a code, IF(ABS(var_pct) <= threshold_pct, "Within_Range", "Review"); a code its dimension does not have is #N/A. A file import and the AI Developer's write_input_values take the member's code or label; POST /api/cells takes "member". Charts cannot plot a pick-list (count or sum by it instead). Renaming a member's code keeps the cells holding it; deleting a member or a dimension that pick-lists hold is refused (409). Revision copies, model export and import carry the dimension.
Text cells: a note beside the number. An Input metric of format Text holds free text in each cell — a planner's comment on a correction, an activity's owner, a source note: a spreadsheet's comment column. In the grid the cell is a text box; emptying it clears the cell. A text metric has no total (its aggregation and time summary are None) and formulas do not read it (TEXT_METRIC_IN_FORMULA). File imports read the column's text as it is, the AI Developer's write_input_values takes the note as text, POST /api/cells takes "text"; grid exports write the note, the cell history keeps every version, and revision copies and model export carry them. A calculated metric of format Text shows its number, as before.
Clearing a cell. Emptying an input cell in the grid — deleting its number, choosing "—" in a pick-list, emptying a note — clears it: the cell has no value, not 0, which matters to AVERAGEIFS, COUNTIFS and a blank display. The typed value goes to the cell history with the reason "cleared"; values a form integration posted stay. Over the API, POST /api/cells with "clear": true. A write naming a member code its dimension does not have is refused (400) — it used to be stored where nothing read it.
Highlight rules: a spreadsheet's conditional formatting. Edit a metric and, under Highlight cells, add rules: When this cell (or another metric at the same cell), optionally absolute, a comparison (> ≥ < ≤ = ≠ between, not between, is blank, is not blank) with a value or a metric, → a tone (Red, Amber, Green, Blue). The first rule that holds tints the cell, on leaves and totals alike. A metric compared with is read at the same cell when it is on the grid, else at its total — a threshold setting on another grid. The workbook rule ABS(S5)>Setup!$B$12 on a Var % column is "When this cell, absolute, > the metric threshold_pct → Red"; "= Review" on a pick-list compares its member's code. The metric row shows "1 highlight". Rules name metrics as formulas do, so revision copies and model export carry them; over the API they are highlight_rules (see HighlightRule in api/openapi.yaml).
Formula language in short. Optional leading =; names are case-insensitive; operators + - * / ^, comparisons = <> < <= > >=, text join &, parentheses; arguments separated by commas or semicolons. Functions: see Concepts › Formulas. A formula can read the cell's member (region), a member property (employees.salary), the parent member (PARENT(region)), another member's value (LOOKUP) and conditional totals (SUMIFS and its family). Not available: cell addresses like A1, XLOOKUP/INDEX/MATCH. Offsets between periods use the time-series functions on a Time dimension.

Dimensions

Sidebar: Build › Dimensions

A dimension is an axis of the model (Department, Region, Product, Period). Its members are the values on that axis, optionally arranged in a hierarchy, and each member can carry property values used for grouping and rollups. A dimension is either Standard or Time — chosen explicitly when it is created and fixed afterwards. Only a Time dimension gives formulas a calendar to move along (PREVIOUS, LAG, MOVINGSUM, …); naming a standard dimension "month" does not.

Rules and behaviour

  • Codes are identity. Data, imports and formulas refer to members by code; labels are for display. Changing a code re-keys the member for future writes.
  • Hierarchy and totals. A parent's value is the rollup of its children using the dimension's rollup rule (sum by default). Grids can show all levels, one level, or leaves only (Grids › Show).
  • Member order. Grids, selectors, charts and model export list a dimension's members in the dimension's own order, not by code. Move up and Move down on a member row swap the member with the sibling above or below it — the members under the same parent, or the top-level members; in a child dimension, the members under the same parent-dimension member. A member never leaves its parent this way; Parent member in Edit does that. The arrow at the end of a level is disabled, and both are while a search narrows the tree, because the search hides the siblings they would swap with ("Clear the search to reorder"). A new member goes last among its siblings. A member given a new parent keeps its position number, so its place among its new siblings is not fixed (it can come first); use the arrows to put it where it belongs. A Time dimension has no arrows: its periods keep calendar order, and a reorder of one is refused with "time periods keep calendar order". The AI Developer's reorder_dimension_members sets the same order; over the API it is PUT /api/developer/dimensions/{dimId}/members/order. The order belongs to the revision: revision copies and model export carry it.
  • Deleting a member deletes its descendants and triggers recalculation of every metric that had values there. The member's input values are deleted with it; the cell history keeps them.
  • Property groupings. A dimension can group another dimension's members by a declared property: New dimension › Standard › Group members of employees By property area creates area, whose member North stands for every employee whose area value is exactly North. Tick one member per value to create a member for each distinct value; later, Derive members on the card adds members for values that appeared since (a value without a member is under no group). A metric on employees then totals by area: placed on a grid with area (=salary), in =SUMIFS(salary, area, "North") and in =LOOKUP(salary, area, "North"). Editing an employee's area recalculates them. The rules, refused with INVALID_GROUPING: the grouped dimension is a Standard dimension of the same revision, not the dimension itself and not in a cycle; the property is declared on it; neither side is a Time dimension; a dimension has a parent dimension or a grouping, not both. The property a grouping uses cannot be deleted (PROPERTY_IN_USE), and renaming it carries the grouping along. Over the API: POST /api/developer/dimensions with source_dimension_id, source_property and derive_members; PATCH changes the property, re-derives, or clears the grouping with source_dimension_id: null (refused with 409 while a formula names the dimension). Revision copies, model export and import keep the grouping pointed at the copy's own source dimension.
  • Properties in formulas. Declare the property here with its type, then write dimension.property: =headcount * employees.salary reads a number, =SUMIFS(salary, employees.region, "EMEA") uses a text property as a criterion, =LOOKUP(fx_rate, currency, entity.currency) uses it as a member code. A number property whose value does not parse gives #VALUE!; an empty value is blank. A formula naming an undeclared property is refused when the metric is saved.
  • Changes recalculate. Adding, editing or deleting a member, and adding, renaming, retyping or deleting a property, recalculates every metric whose formula uses the dimension. Renaming a property also renames it in every member's values, in any property-derived grouping and in every formula that reads it, in one step. Deleting a property, or the whole dimension, is refused while a formula still reads it; the message names the metrics to change first. Deleting a member is refused the same way while a formula names its code — a literal member in a LOOKUP, a TIMESUM start or end period, a criterion such as SUMIFS(sales, zone, "Z2"), or a comparison such as IF(zone = "Z2", …); a criterion like "<>Z2" or "Z*" does not count. Renaming a member is not refused and does not change formulas: a formula naming the old code then shows “—” with an error naming the member, and the revision cannot be activated until the formula changes. A new dimension or metric, or a rename, is refused when the revision already has one of that name. Properties declared by a CSV or connector import keep the file's header as their name; a header that is not an identifier cannot be used in a formula.
  • Calculated members. A top-level member of a standard dimension can be computed from the dimension's other members, for every metric: edit the member and give it a formula such as {RF} - {LY}. The formula names member codes and may use IF, ABS, MIN, MAX, ROUND, AND, OR, NOT and METRICFORMAT(), the format of the metric it is computed for, so a margin's variance can be in points: IF(METRICFORMAT() = "percentage", {RF} - {LY}, IF({LY} = 0, 0, ({RF} - {LY}) / ABS({LY}) * 100)). Its value at every level is computed from its siblings there: the FY variance % from the FY values, never the months' percentages added up. It holds no input, is in no total, and cannot have members under it; a metric formula reads the members it is computed from, not the calculated member. This is the comparison layout: one scenario dimension (RF, LY, Variance, Variance %) on the P&L grid and one metric per line reading the scenario (=IF(scenario = "RF", rev_rf, rev_ly)), instead of a copy of every line per block. Renaming a member updates the formulas that name it; a member a formula names cannot be deleted.
  • Members business users keep. Edit a standard dimension's header and tick Business users maintain its members (the card shows "business-maintained"): on any grid whose rows are that dimension, business users then add a member (Add <dimension> under the table: a name, and its parent when the leaves sit under parents), rename one and remove one (icons on the row, on hover) — a planner naming a new strategic activity. Only labels and declared properties are theirs: the code is generated when they give none (the next of the dimension's numbered codes, STRAT-021, else the name in capitals), and codes, parents, periods and the dimension itself stay the developer's. Each change is held to the business user's own access: the open revision, the write guard on the parent or member (hidden or read-only members, a system-managed revision, a workflow lock), and a member with members under it, one a formula names or a pick-list cell holds, cannot be removed. A time dimension or a property grouping cannot be business-maintained. Their routes are POST/PATCH/DELETE /api/dimensions/{dimId}/members.
  • Dimensions are per revision, like everything else under Build.
