Models

Sidebar: Build › Models

The Models screen lists every application and model you can reach, with their revisions. It is where you choose which revision you are editing; every other Build screen works inside that choice.

Controls

ControlWhat it does
Banner Working in revision: …The revision every Build screen edits, with its short id. With nothing selected the banner is orange: "No revision selected — select a revision below to start working".
Revision rowClick to select it. The row gets a Working badge; a live badge marks the model's active revision.
Set activeOn a non-active revision. Confirm Set as active revision?: the revision "becomes the live revision everyone sees. This can be changed again later."
Delete revision iconOn a non-active revision. Confirm Delete revision?: "This permanently removes the revision. This cannot be undone." The active revision cannot be deleted.
New revisionType a name, press Enter or Save. The new revision is a full copy of the model's current state (see Concepts › Revisions).
Set as business default / badge business defaultBusiness consoles (dashboards, workflows, grids) open the default model of an application. With several models in one application, pick which one users get.

Rules and behaviour

  • Selection is per session and not saved. On a fresh sign-in the console pre-selects the most recently created revision, and if you skip this screen it falls back to a default revision that may belong to another application. Check the header (Model and Revision) before creating anything.
  • Applications and models are created by administrators (Applications screen of the tenant or platform admin). A developer creates revisions, not applications.
  • Active means live. Business users always see the active revision. Build and test in a non-active revision, then Set active.

Metrics

Sidebar: Build › Metrics

A metric is a measure of the model: an Input metric is typed in by users, imported or posted from forms; a Calc metric is computed from a formula over other metrics. The list groups inputs first, then a Calculated section.

The list

ControlWhat it does
Search metrics…Filters by name or label; the footer reads "n results of m metrics".
Header lineApp and model name and the model's short id, so you can confirm what you are editing.
Used byThe calculated metrics whose formulas reference this row. This is the dependency graph in table form.
Edit iconTurns the row into an inline editor (below).
Delete iconConfirm Delete metric?: "This removes the metric from all formulas that reference it." Dependents are recalculated afterwards.
Add metric / CancelOpens the add form under the list.

The add form

FieldMeaning
Metric nameTechnical name in snake_case; formulas refer to it. Example gross_margin.
TypeCalc or Input. Choosing Input clears the formula.
FormatNumber, Percentage, Currency, Boolean, Text. Currency adds Decimal places (0–4) and Symbol (default $). Number and Percentage also take decimal places.
Formula (Calc only)Spreadsheet-style expression over metric names, for example =revenue - cogs or {hc_cost} + {software_cost}. Each {name} reference shows a green ✓ or a red "✗ unknown" badge below the field.
Aggregation rule (Calc only in the add form; both types when editing)How per-member results combine into totals: Sum, Average, Count, Rate, Formula. Rate asks for a Numerator and a Denominator metric ("total = numerator ÷ denominator"), so the total reflects weight instead of averaging members. Formula evaluates this metric's own formula on aggregated inputs, which is what ratios and percentages need. Formula is refused for input metrics.
Add metricEnabled when the name is filled, a Calc metric has a formula with only known references, and a Rate rule has both operands. After success the label reads Added and the form stays open for the next metric.

Editing

  • Saving a changed formula or rule triggers recalculation; the row then shows a green Recalc results banner listing "revision → metric = value" per affected total. Dismiss it with the ×.
  • Formula references are validated by the server's parser (both =name and {name} styles). Save is disabled while any reference is unknown.
  • The type (Input or Calc) cannot be changed after creation; create a new metric instead.
Formula language in short. Optional leading =; names are case-insensitive; operators + - * / ^, comparisons = <> < <= > >=, text join &, parentheses; arguments separated by commas or semicolons. Functions: see Concepts › Formulas. Not available: cell addresses like A1, SUMIF-style conditional aggregates, lookups, dotted property references, offsets between periods.

Dimensions

Sidebar: Build › Dimensions

A dimension is an axis of the model (Department, Region, Product, Period). Its members are the values on that axis, optionally arranged in a hierarchy, and each member can carry property values used for grouping and rollups.

Controls

ControlWhat it does
New dimension / CancelOpens the form: Name (placeholder department) and Parent dimension (optional). Create.
Parent dimensionMakes this a child dimension of another one: the card shows "child of <parent>", the add button reads Add member and each member's parent is picked from the parent dimension's members ("— unassigned" when none). Use it for a second level that is defined separately, for example Cost Centre under Department.
Card header"n members · n roots · rollup: sum". Props / Hide props toggles the property columns. Expand-all and collapse-all icons. Edit-name icon. Delete icon: confirm Delete dimension? "This removes the dimension and all its n members."
Search members…Filters the tree.
Member rowLabel (indented per level, chevron to expand), Code, Children count, actions: Add child (+), Edit, Delete (confirm Delete member?, mentions descendants).
Add root memberInline row: CODE (monospace), Label, then Save. Adding a child pre-sets the parent.
Edit memberSame inline row plus Parent member select (move within the hierarchy) and one input per property.
Dimension Properties"usable in formulas as dim.propertyName". Add with property_name and a type (text, number, date), then Add. Each property becomes a column in the member table when props are shown; values are edited per member.

Rules and behaviour

  • Codes are identity. Data, imports and formulas refer to members by code; labels are for display. Changing a code re-keys the member for future writes.
  • Hierarchy and totals. A parent's value is the rollup of its children using the dimension's rollup rule (sum by default). Grids can show all levels, one level, or leaves only (Grids › Show).
  • Deleting a member deletes its descendants and triggers recalculation of every metric that had values there.
  • Properties are the basis of property-derived groupings (for example grouping cost centres by their region property). Editing property values per member is available here; building derived dimensions from properties is only partly exposed in the console.
  • Dimensions are per revision, like everything else under Build.

Dependency Graph

Sidebar: Build › Dependency Graph

A read-only map of every metric in the revision and the arrows between them: an arrow from A to B means B's formula uses A. Use it to understand what a change will recalculate and to spot metrics that are on no grid.
