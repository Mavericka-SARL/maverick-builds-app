Integrations

Sidebar: Developer › Integrations

Integrations bring data in and out of the model without typing: file uploads, a Google Sheet (link-shared, or private through the tenant's service account), any JSON REST API, and posting of form records into planning cells. The screen opens with one tile per source; selecting a tile shows that source's list and actions below.

Excel / CSV Import

New Import opens the four-step Import Wizard: Upload, Map Columns, Validate, Commit. The section also lists Saved Integrations and Recent Imports.

Step / fieldMeaning
Import target typeGrid, Form or Dimension, then the specific grid, form or dimension.
Target revisionRequired. The revision the data goes into; the active one is marked "(active)".
Import modeIncremental: add each imported value to the cell's current value, keep everything else. Full reload: delete all data for this revision, then insert.
FileDrop or browse: .csv, .xlsx, .xls. For workbooks a Sheet select picks the worksheet.
Map ColumnsOne row per source column with sample values and a target select: (ignore), the target's fields (required ones marked *), and for dimensions new property… with a property name. You can name the mapping and Save as draft to finish later, or save it as a reusable integration.
ValidateCounts Total rows, Valid, Errors, Warnings with a per-row issue list (for example "Empty row — will be skipped"). Choose to import valid rows only or Import All Anyway.
CommitA Confirm Import summary (target, revision, rows, columns mapped, rows skipped), then Import Complete or Import Failed with the reason.

File layout by target. Grid: one column per dimension holding leaf member codes, and either one column per metric named after it (wide) or a column of metric names mapped to metric with the amounts in a column mapped to value (long). Values may be negative. Form: one column per form field name. Dimension: code, label and optionally parent_code.

Files laid out for people. A workbook with a title above the header, months across the columns, a label written once per group, total rows or amounts in thousands does not need fixing by hand. The wizard's Shape step, after the upload, sets the Header row (the file as read is shown with its row numbers), Fill down columns, rules to Skip rows ("Total"), Columns into rows (Jan…Dec into a Month column and a value column), Fixed values (Scenario = Budget), Rename values (labels to member codes) and Numbers (decimal comma, a column in thousands). Preview shows the rows as the import will read them, and the next step maps those columns. With nothing set, the file is read as it is. Save as integration keeps the shape, and it applies to every later file of that layout; the integration's line then reads Reshapes each file: …, Run with a file imports a file as it is, and Edit shape and mapping changes them on a sample file without importing. The AI Developer can set the same shape up, and can hand back a converted file as CSV or Excel.

Running a saved integration with a new file. The integration keeps its column mapping, so the next file only has to have the same columns. Run Import opens the wizard with it; on a dashboard, an Integration button lets a user pick a .csv, .xlsx or .xlsm file and imports it straight away with the saved mapping and mode: valid rows are imported, and the first failing row is named under the button. Every run, from either place, is in the integration's Run history.

Saved Integrations lists CSV and Google Sheets integrations with a status badge, tags, Sync Now (Sheets), Run history and Delete integration ("removes the integration and its import history"). Double-click a name to rename. Recent Imports shows each import job with its status (Validating, Committed, error) and a delete action.

Imports write to the revision you choose and respect the same rules as typing. Hidden or read-only members, calculated metrics, locked workflow scopes and system-managed revisions are refused row by row. Each committed import triggers recalculation and can start a workflow through an integration trigger.

Google Sheets

  • Google Sheet URL and Fetch. Either the sheet is shared as "Anyone with the link → Viewer", or a Google service account is stored in the Private sheets panel at the bottom of this section (paste the JSON key file Google Cloud downloaded; only its address and private key are kept, encrypted) — then a sheet shared with that account's address, shown in the panel, is read privately, with nothing else changed. No personal Google account is ever connected. The worksheet tab in the URL (gid) is the one fetched.
  • Layout matches the CSV formats. Mapping, validation and commit are the same wizard steps.
  • Import mode for Sheets is Sync (replace listed cells) by default: the sheet is authoritative for the cells it contains, so re-syncing converges instead of double-counting. Full reload is also offered.
  • A saved Sheets integration re-fetches the sheet on every Sync Now.

REST API

New integration opens the builder with steps Basics, Request, Authentication, Test & response, Mapping, Run & schedule. Save draft keeps work in progress; Activate requires a successful test of the current configuration.

StepFields
BasicsName, Description, Tags, Direction (Pull: external API → Mavericks; Push: Mavericks → external API), Target type (Grid, Form, Dimension) and the target. Pull: Import mode (incremental adds to existing values; replace overwrites matched cells; full reload wipes the target first). Push: Push mode (one request per record, or one batched JSON request).
RequestSource: HTTPS API, SFTP server, or another model of this tenant (both below). For an API: Method (GET, POST, PUT, PATCH, DELETE), Request URL, Query parameters and Headers as key/value rows with an enable checkbox, Body (None, JSON, Form URL-encoded, Raw text with Content type), Insert variable… to add template variables, Timeout (s) (default 30, max 120), Max retries (mutations need an idempotency key).
AuthenticationAuthentication type: None, API key (header or query), Bearer token, Basic auth, OAuth 2.0 client credentials, OAuth 2.0 authorization code. Credentials live in a reusable Connection, stored encrypted; New connection, Check credential, and Keep / Replace / Remove on an existing one. The secret value is never shown again. Authorization code is the flow for a provider that must ask a person: enter its authorization and token URLs, client id and secret and the scope, then press Connect — the provider's consent page opens, and on return the connection holds the tokens; scheduled runs refresh them on their own. Disconnect forgets the tokens and keeps the client. The provider must be given this platform's callback address, shown next to the button. An SFTP source offers User name and password or SSH private key (OpenSSH or PEM, with an optional passphrase).
Test & responseResponse format (JSON, CSV), Records path such as $.data.items, Send test request. A test really calls the external system; for non-GET methods a confirmation warns "This test may change external data". The step shows the inferred fields and a safe subset of response headers; activation needs a passed test.
MappingResponse shape: Wide (one column per metric) or Long (Metric name field and Value field). Then field mappings: source path (for example $.field, with inferred fields offered) → target (grouped Dimensions and Input metrics; for push, the outbound JSON property), each with an optional transform (date format, default value, value map "a=b, c=d"). Push batches take Batch property (default "items") and Batch size.
Run & scheduleExecution: Manual only, Interval (Every (seconds), minimum 60), Daily, Weekly, Advanced (cron, five fields), with Timezone (IANA), Overlap policy (skip this tick, or queue behind it) and a Schedule enabled switch. Limits: Max pages, Max records, Max requests, Failure threshold (abort after this many bad records).

Reading a file from an SFTP server. On the Request step, Source → SFTP server (a spreadsheet file) reads one .csv, .xlsx or .xlsm file instead of calling an API; it imports only (pull). The fields are Server (a name or address; port 22 only) and File: A fixed file at a File path, or The newest file in a folder that matches a pattern, with a Folder (empty means the login folder) and a File name pattern such as sales_*.xlsx. Of the matching spreadsheet files, the most recently modified one is read. Sheet (empty means the first), Header row and CSV delimiter say how to read it. The first Test: read the file reads nothing: it shows the server's host key fingerprint. Compare it with the server's, press Trust this key, and test again. If the server later presents a different key, runs are refused until the new key is trusted. The file stays on the server after a run. A scheduled run skips a file identical to the one the last import read; Run now always imports. Files may be up to 16 MB.

Limit: no Shape step for an SFTP file. The wizard sets only the Sheet, Header row and CSV delimiter: the Import Wizard's Shape step previews a file in the browser, and an SFTP file never reaches the browser. A file laid out for people (fill-down columns, rows to skip, months across, constants, value maps, a scale) can be shaped through the HTTP API for now. Read the integration with GET /api/developer/integrations/{id}, add sftp.reshape to its config (the same settings as the Shape step: header_row, fill_down, skip_rows, unpivot, constants, value_map, scale), send the whole config back with PATCH /api/developer/integrations/{id}, then test and activate it again. Validate reports settings the file reader cannot apply.

Reading another model (a model link). On the Request step, Source → Another model of this tenant (a grid) imports a grid of another model — of this application or another one in your tenant — into this model; it imports only (pull). Choose the Model (only models you are a developer of are offered), its Grid, optionally the Metrics to take (none ticked takes all of them, calculated metrics included) and Filters that keep only some members (a parent keeps every member under it), and whether records carry member Codes or Labels. Each record is one combination of members with a value: a field per dimension and per metric, named as in the source ($.region, $.revenue), mapped on the Mapping step as for any other source. A link needs no sign-in: it reads the source grid as its owner — the developer of both models who created it, or who last changed what it reads or activated it — with exactly the values the owner sees there, whoever starts the run. It always reads the source model's active revision, so it follows the source's promotions; the grid is found by its name, and a grid renamed away fails the run until the link is pointed at it again. Its Import mode is Replace or Full reload: each run reads the source's values as they stand, which Incremental would add a second time.

RuleWhat it means
Who sets it upOnly a developer of both models creates a link, changes what it reads, activates it or tests it, and doing so makes them its owner. Any developer of its own model can rename it, tag it, schedule it, switch it off or delete it.
Who runs itAnyone who may run the integration: a developer with Run now, its schedule, or a user pressing a dashboard Integration button — who needs no access to the source model. Every run reads as the owner. Every run checks again that the owner is still a developer of both models; once they are not, the link has stopped and every run is refused with that reason, a button press included, until a developer of both activates it again and becomes its owner.
Two switchesA link runs only while both sides are on. Its own model's switch is the integration's on/off control, per revision as for any integration. The source model's switch is in that model's Integrations › REST API › Links reading this model list, held by its developers; it applies to every revision copy of the link, so promoting a revision copied before a switch-off does not bring the link back. Tenant administrators hold both switches in Tenant admin › Model links. Switching either side off stops every scheduled or manual run that has not started yet (one already running finishes), and a source-side switch-off stops tests too.
Same tenantA link reads a model of its own tenant only, never another tenant's.
Revisions and packagesA new revision copies its links with their source and switches. An exported model package carries a link without its source model: imported elsewhere it arrives as a draft, keeping the grid, metrics and filters it read, to be pointed at a model there.
Limit: cells emptied in the source stay in this model. Replace overwrites the cells a run writes; a value removed from the source grid is not written, so its last copy stays here. Full reload clears this revision's values first, every grid's, so use it only for a model whose values all come from links or imports.

The list shows each integration with its status and actions; deleting removes "the definition, its schedule and run history" and any dashboard buttons that reference it. Run history shows per run: status, trigger, started, duration, HTTP status, pages, requests, retries, read, written, skipped.

Where REST integrations surface. A dashboard Integration button lets a user run one on demand — a model link too, read as its owner. An integration's "import completed" and "import failed" events can start a workflow (Workflows › Starts on; Triggers). A switched-off or draft integration's schedule runs nothing; switching it back on does not run the times it missed.

Posted values are ordinary input values: they recalculate dependents and obey access rules and locks. Metric-typed form fields ("By name") let one form feed different metrics per record.

Data Export

A data export is a saved, re-downloadable file of one grid's values in the format another system expects. New export opens the editor; its preview updates as you change it, and an export that cannot be produced lists every reason and cannot be saved.

FieldMeaning
Name, Grid, TagsThe grid is fixed once saved; create another export for another grid.
FormatCSV, Excel or JSON (an array of objects keyed by column).
LayoutMetrics as columns (one column per metric), One row per value (metric and value columns) or Members as columns (the leaf members of the dimension chosen under Members across from, for example periods across).
MetricsAll of the grid's metrics, including ones added later, or a chosen set. Calculated metrics export their calculated values.
Dimension columnsWhich dimensions are columns, in which order. Exports are leaf-level, one row per leaf combination: a dimension that is not a column must be filtered to exactly one leaf member.
FiltersMembers to keep per dimension; a parent keeps every leaf under it.
Members as, Metrics asCodes, labels, or a code and a label column; metric names or labels.
Decimals, Delimiter, Decimal separator, Sheet name, File nameRounding; for CSV the delimiter (comma, semicolon, tab, pipe) and decimal separator (a decimal comma needs another delimiter); the Excel sheet's name; the file's name without extension.
Header row, Include combinations without valuesWhether CSV and Excel start with a header row; whether every leaf combination gets a row, even with no values.
Column namesRename any column as it should appear in the file.

Each card has Download, edit and delete. A download is built when it is asked for, from the downloader's own view of the grid: members and metrics hidden from them are left out, and every value is the one their grid shows. Put an export on a dashboard with an Integration button and users download it there; each download is kept in the export's run history. The AI Developer creates exports the same way (see the AI chapter), and can import a spreadsheet attached to its chat into a grid or dimension.
